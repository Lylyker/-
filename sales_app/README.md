# Многопоточное приложение обработки информации о продажах (C, POSIX threads)

## Архитектура — 5 потоков
| № | Поток          | Файл                 | Задача |
|---|----------------|----------------------|--------|
| 1 | Симуляция продаж | `sim_thread.c`     | Генерирует случайные продажи с интервалом 1–4 с и безопасно дописывает их в `sales.txt` (формат: `ID_продажи;дата_время;ID_покупателя;ID_товара`) |
| 2 | Агрегация       | `analytics_threads.c` | Каждые ~5 с читает файл и печатает текущую сумму всех продаж |
| 3 | Ранжирование    | `analytics_threads.c` | Топ-5 самых популярных и топ-5 самых непопулярных товаров |
| 4 | VIP-фильтрация  | `analytics_threads.c` | Покупатели, набравшие товаров на сумму больше порога `g_vip_threshold` |
| 5 | CLI-интерфейс   | `cli_thread.c`       | Бесконечный цикл: приём команд, изменение порога + `pthread_cond_broadcast`, команда `exit` |

## Синхронизация
- `g_file_mutex` — критическая секция чтения/записи `sales.txt`;
- `g_param_mutex` — защита глобальных параметров (`g_vip_threshold`, версии данных);
- `g_data_ready` — broadcast из потока симуляции: «появились новые продажи»;
- `g_param_changed` — broadcast из CLI: «изменён порог, пересчитаться!».

## Сборка и запуск
```sh
make            # gcc -Wall -Wextra -O2 -std=gnu11 -pthread
./sales_app     # или: make run
```
Команды в консоли приложения:
- `<число>` — новый порог VIP (например `50000`);
- `threshold` — показать текущий порог;
- `help` — справка;
- `exit` — корректное завершение всех потоков.

## Файлы
- `app.h` — структуры, глобальные переменные, прототипы;
- `main.c` — инициализация примитивов, создание 5 потоков, `pthread_join`;
- `logger.c` — потокобезопасное логирование с временными метками в `app.log`;
- `data.c` — загрузка/генерация тестовых `products.txt`, `customers.txt`, парсинг `sales.txt`.
